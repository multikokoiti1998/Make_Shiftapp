# 勤務表テンプレート改修プラン

前提資料: [`勤務表シート構成.md`](./勤務表シート構成.md)（22シートの役割分類）

## 1. 目的・前提

Shiftapp_demoの「勤務表Excel出力」機能は、テンプレート内の「デイリーデータ」シートを書き換えるだけで残り21シートが数式で自動再計算される、という仕組みに乗っている。テンプレート自体は長年の運用でシートが積み重なっており、

- どこからも参照されていない死んだシートが混ざっている
- ほぼ同じ数式を持つシートが複製されている
- 存在しない古いファイルへの外部リンクが残っている

といった「積年の汚れ」がある。これを整理してテンプレートの保守性を上げ、将来アプリ側から自動生成・自動検証しやすい形にするのがこの改修の狙い。

**大前提**: このExcelは部署が実際に印刷・押印・TimePro提出・拘束担当依頼などの本番業務に使っている。**現行の本番運用を壊さないことを最優先**とし、確証のある変更から段階的に進める。一括の大改造はしない。

## 2. フェーズ0 — 調査で安全性が確認済み、すぐ実施できる削除

| 対象 | 根拠 | 作業 |
|---|---|---|
| 「勤務表」シート（"(2)"なしの方） | 他のどのシートの数式からも参照されていない（参照0件）。`ShiftExcelReader`が読むのも「勤務表 (2)」のみ | Excelで開いて手作業のメモ・コメント・印刷設定が残っていないか目視確認 → 削除 → 「勤務表 (2)」の表示とアプリのExcel読込結果に影響が無いことをテスト |
| `勤務変更YY-MM.xlsm`の古い外部リンク | `勤務表(2019-11).xlsx`・`勤務表(2021-02).xlsx`・`勤務表(2021-04).xlsx`など、存在しないはずの年度への外部リンクが6本中3〜4本残存 | Excelの「リンクの編集」で参照先を確認し、実際に使っていないリンクを解除 |
| `らいふクリニック.xlsm`の`Sheet1` | 既定シート名のまま・32行のみ・他から参照なし。作業用に残った空きシートの可能性が高い | 中身を確認し、空/不要なら削除 |

いずれも「参照されていない」「存在しないファイルを指している」という機械的な事実で判断できるため、他フェーズより先に着手してよい。

## 3. フェーズ1 — 現場確認が必要な削除候補

以下は数式チェーン上は末端（他から参照されていない）だが、部署の実運用（印刷して配布・提出）で使われている可能性があるため、**削除前に関係者へのヒアリングが必要**。

- 印刷用／印刷用２（印刷レイアウト） — 今も紙で配布しているか？両方使っているか、片方は旧版か？
- 管理課提出用データ — 今も管理課へこの形式で提出しているか？
- マニュアル — 中身の説明書きは現行の運用と一致しているか、まだ参照されているか？
- 月表示 — 誰かが日常的に見ているか？

ヒアリング結果を踏まえ、不要と判明したものから順に削除する。

## 4. フェーズ2 — 当直系カレンダー6シートの集約（中期対応・要検証）

### 発見した実態
「当」「明」「●」「午前半」「日勤」「例外」の6シート（各A1:AH101、合計約24,000セル、いずれもほぼ非表示）は、**行1のヘッダー生成式から行53以降のスタッフ参照ブロックまで、数式がほぼ完全に同一**。唯一の違いは各シートのセル`$A$1`に入っている記号だけ:

| シート | `$A$1`の値 | 意味 |
|---|---|---|
| 当 | 当 | 当直（夜勤） |
| 明 | 明 | 明け（当直翌日） |
| ● | ● | 休み記号 |
| 午前半 | ／ | 午前半日 |
| 日勤 | 日勤 | 日勤（`COUNTBLANK`使用で若干ロジックが異なる） |
| 例外 | 例外 | 例外 |

行55付近の集計式は共通して
```
IF(COUNTIF('勤務表 (2)'!D$3:D5, <シート名>!$A$1) = COUNTIF('勤務表 (2)'!D$3:D4, <シート名>!$A$1), "", COUNTIF(...))
```
という形で、「`勤務表 (2)`の中でその記号が何日目に何回目として出たか」を数えているだけ。つまり6シートは**パラメータが1つ違うだけの手作業コピー**になっている。

### 改修案

**案B（推奨・低リスク）**: シート構成はそのまま残し、行53以降の「スタッフ参照ブロック」（6シートで完全重複している部分）だけを1箇所（例えば既存の`スタッフ`シートの余白か新規の共通ブロック）に集約し、各シートはそこを参照する形に書き換える。見た目・シート数は変えないため、部署側の操作感に影響がなく、変更範囲を数式の一部に限定できる。

**案A（効果大・高リスク）**: 6シートを1シートに統合し、`$A$1`相当の記号を列（または別テーブルのキー）としてパラメータ化した集計テーブル（日付×記号のCOUNTIFS表）に置き換える。シート数を6→1に減らせるが、既存の数式・印刷レイアウト・条件付き書式が6シートの物理的な存在を前提にしている可能性があり、全面的な書き換えと動作確認が必要。

→ まずは**案Bから着手**し、十分に安定運用できた後で余力があれば案Aを検討する、という2段階を推奨する。

### 実施時の検証方法（必須）
1. 改修前のテンプレートで、ある月のデータを使って「勤務表 (2)」「印刷用」「印刷用２」を出力し、セル値をすべて控えておく（スクリーンショットまたはCSVエクスポート）。
2. 改修後のテンプレートで同じ月のデータを使い、同じ出力を得る。
3. セル単位で差分がゼロであることを確認してから、本番テンプレートを差し替える。
4. 差分が出た場合は原因（参照範囲のズレ等）を特定するまで本番反映しない。

## 5. フェーズ3 — アプリとテンプレートの境界の明確化

Shiftapp_demoのC#コードには「宅直」「拘束」という語が一切登場せず、以下のシート群は**アプリが完全に関知していない、部署内だけの別業務**であることを確認済み:

- 宅直データ／宅直データ (２)
- 拘／拘束者／拘束担当依頼表
- らいふクリニック（非表示、`らいふクリニック.xlsm`から手動転記）

これらを「今のテンプレートに残したまま」にするか「別ファイルに分離する」かは、アプリの技術的な都合ではなく**部署の運用判断**に委ねるべき事項として明記する。現時点では無理に触らず、フェーズ0〜2の対象からも除外する。
